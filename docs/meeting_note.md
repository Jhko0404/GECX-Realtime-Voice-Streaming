본사 실시간 STT 레이턴시(0.3~0.5초) 최적화 및 타임아웃 방어
1. 현업 요구(0.3~0.5초)와 LLM 추론 시간(1~2초) 간의 갭 해결
배경: 본사 파일 검색 시스템(Knowledge Ocean)이 단순 역색인 기반으로 0.5초 만에 응답함에 따라, 현업에서 AI 추천 답변에도 동일한 속도를 요구함.
최적화 전략:
스트리밍 청킹 (Streaming Chunking): 전체 문장 완성을 기다리지 않고 첫 토큰부터 실시간 타이핑 형태로 UI에 스트리밍하여 체감 지연 시간을 0.5초대로 단축.
앞단 FAQ 인메모리 캐싱: 상담원들이 매일 반복 질문하는 상위 30% 빈출 질의는 LLM을 거치지 않고 캐시에서 0.1초 만에 즉시 표출.
STT 텍스트 표출과 의도 분석 분리: STT 텍스트는 즉시 화면에 뿌리고, 키워드 하이라이팅 및 의도 분석은 비동기 백그라운드로 처리.
2. 10분 오디오 스트리밍 시 소켓 세션 타임아웃 (1분 20초~2분 끊김)
긴 통화 스트리밍 시 80초~120초 사이에 GCP API 소켓 세션이 종료되는 현상 확인.
GCP 음성 스트리밍 API 기본 Quota 및 타임아웃 정책을 점검하고, 클라이언트 단에서 세션 ID를 유지하며 버퍼를 재전송하는 자동 재연결(Reconnection Handler) 로직 구축.
